#45: Returning a nil receiver
func main() {
var foo *Foo
fmt.Println(foo.Bar())
}
foo is initialized to the zero value of a pointer: nil. But this code compiles, and it
prints bar if we run it. A nil pointer is a valid receiver.
 But why is this the case? In Go, a method is just syntactic sugar for a function whose
first parameter is the receiver. Hence, the Bar method we’ve seen is similar to this
function:
func Bar(foo *Foo) string {
return "bar"
}
We know that passing a nil pointer to a function is valid. Therefore, using a nil pointer
as a receiver is also valid.
 Let’s get back to our initial example:
func (c Customer) Validate() error {
var m *MultiError
if c.Age < 0 {
// ...
}
if c.Name == "" {
// ...
}
return m
}
m is initialized to the zero value of a pointer: nil. Then, if all the checks are valid, the
argument provided to the return statement isn’t nil directly but a nil pointer.
Because a nil pointer is a valid receiver, converting the result into an interface won’t
yield a nil value. In other words, the caller of Validate will always get a non-nil error.

in Go, an interface is a dispatch wrapper. Here,
the wrappee is nil (the MultiError pointer),
