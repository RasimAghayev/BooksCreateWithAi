 An interface should live on the consumer side in most cases. However, in particu-
lar contexts (for example, when we know—not foresee—that an abstraction will be
helpful for consumers), we may want to have it on the producer side. If we do, we
should strive to keep it as minimal as possible, increasing its reusability potential and
making it more easily composable.

#7: Returning interfaces
While designing a function signature, we may have to return either an interface or a
concrete implementation. Let’s understand why returning an interface is, in many
cases, considered a bad practice in Go.
 We just presented why interfaces live, in general, on the consumer side. Figure 2.7
shows what would happen dependency-wise if a function returns an interface instead
of a struct. We will see that it leads to issues.
