8.13
Specify capacity explicitly in subslice expression
In Go, at compile time, if it is not obviously (for the compiler) to deduce the capacity of a subslice
expression s[a:b:c] is non-zero, then the compiler will generate several extra CPU instructions,
to prevent the underlying element pointer of the result subslice from pointing to the end boundary
of the memory block carrying the elements of s. Because the end boundary might be the (start)
address of another memory block, and pointing to it might prevent the other memory block from
being garbage collected.
For an implementation imperfection, the current official standard Go compiler (v1.19) succeeds to
deduce the capacity of s[i:i+4:i+4] is non-zero, but fails to deduce the capacity of s[i:i+4] is
also non-zero. So the compiler will generate more CPU instructions for the latter. That means the
g function is more performant than the f function in the following code.
package arrays
import "testing"
var N = 1 << 6
var s = make([]byte, N)
var r = make([]byte, N/4)
func f(rs []byte, bs []byte) {
for i, j := 0, 0; i < len(bs) - 3; i += 4 {
s2 := bs[i:i+4]
rs[j] = s2[3] ^ s2[2] ^ s2[1] ^ s2[0]
j++
}
}
func g(rs []byte, bs []byte) {
for i, j := 0, 0; i < len(bs) - 3; i += 4 {
s2 := bs[i:i+4:i+4]
rs[j] = s2[3] ^ s2[2] ^ s2[1] ^ s2[0]
j++
}
}
func Benchmark_f(b *testing.B) {
for i := 0; i < b.N; i++ {
f(r, s)
}
}
