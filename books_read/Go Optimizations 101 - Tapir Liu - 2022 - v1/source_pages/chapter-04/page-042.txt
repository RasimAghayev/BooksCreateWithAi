4.6.3
A reflect.ValueOf function call makes the values referenced by its
argument escape to heap
As of now (Go toolchain v1.19), a call to the reflect.ValueOf function makes the values refer-
ences by its argument escape to heap. This could be proved by the following program.
package main
import "reflect"
func main() {
var n = 1 // moved to heap: n
_ = reflect.ValueOf(&n)
var k = 1
_ = reflect.ValueOf(k) // k escapes to heap
}
Please note that the message k escapes to heap actually means a copy of k escapes to
heap.
The print functions in the fmt standard package all call the reflect.ValueOf function internally,
so the calls to these functions also make the values references by their arguments escape to heap.
For example, in the following code, the variable x will escape to heap, but the variable y doesn’t.
package main
import "fmt"
func main() {
var x = 1 // moved to heap: x
fmt.Println(&x)
var y = 2 // does not escape
println(&y)
}
