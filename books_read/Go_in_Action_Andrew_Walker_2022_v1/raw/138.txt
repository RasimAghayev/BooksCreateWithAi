The reason the new slice has a larger capacity than it needs is because
copying values is an expensive operation, and doing it for every append
would be wasteful, so Go pre-allocates extra memory every time a slice needs
to allocate new storage, so that, over time, the cost incurred by copying
doesn’t happen as much.[10]
Keeping this behavior in mind, what do you think will happen to the capacity
if you append to this same slice again?
Listing 4.38. Appending To A Slice That Has Capacity
slice = append(slice, 50)
fmt.Println(slice)
// output: [10 20 30 40 50]
fmt.Printf("len: %d, cap: %d\n", len(slice), cap(slice))
// output: len: 5, cap: 6
