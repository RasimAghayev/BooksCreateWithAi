Handling errors and panics
But your handler function didn’t do anything to handle the panic! That safety net is
provided by the library. With this in mind, if you were to take the echo service and
turn it into a well-behaving library, you’d slightly modify your architecture so that pan-
ics were handled inside the library.
 When we began working with Go in earnest, we wrote a trivial little library (now
part of github.com/Masterminds/cookoo) to protect us from accidentally unhandled
panics on goroutines. The following listing shows a simplified version of that library.
package safely
import (
     "log"
)
type GoDoer func()
func Go(todo GoDoer) {
     go func() {
            defer func() {
                   if err := recover(); err != nil {
                           log.Printf("Panic in safely.Go: %s", err)
                   }
            }()
            todo()
     }()
}
This simple library provides panic handling, so you don’t have to remember to do it
on your own. The next listing shows an example of safely.Go in action.
package main
import (
     "github.com/Masterminds/cookoo/safely"
     "errors"
     "time"
)
func message() {
     println("Inside goroutine")
     panic(errors.New("Oops!"))
}
func main() {
     safely.Go(message)
     println("Outside goroutine")
     time.Sleep(1000)
}
