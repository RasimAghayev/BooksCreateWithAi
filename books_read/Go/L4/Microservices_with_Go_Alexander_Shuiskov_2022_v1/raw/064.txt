The handler we implemented handles both GET and PUT requests. Note the way we handle some 
special cases such as an empty id value from the request—in that case, we return a special error code, 
http.StatusBadRequest, indicating that the API request was invalid. If the record is not found, 
we return http.StatusNotFound, and if we encounter any unexpected errors when accessing 
our database, we return http.StatusInternalServerError.
Using such standard HTTP error codes helps the clients to differentiate between the types of errors 
and implement the logic for detecting and correctly handling such issues.
