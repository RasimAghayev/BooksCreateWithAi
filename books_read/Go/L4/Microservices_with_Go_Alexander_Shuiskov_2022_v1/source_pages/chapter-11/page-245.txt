We initialize the logger variable by calling the zap.NewProduction function, which returns a 
production-configured logger. This logger omits debug messages, uses JSON as the output format, and 
includes stack traces in the logs. Then, we create a structured log message by including a serviceName 
field by using the zap.String function, which can be used to log string data.
The output of the preceding example is as follows:
{"level":"info","ts":1257894000,"caller":"sandbox1575103092/
prog.go:11","msg":"Started the 
service","serviceName":"metadata"}
The zap library offers support for other types of Go primitives, such as int, long, bool, and many 
more. Corresponding functions for creating log field names follow the same naming format, such as 
Int, Long, and Bool. Additionally, zap includes a set of functions for the other built-in Go types, 
such as time.Duration. The following code shows an example of a time.Duration field:
logger.Info("Request timed out", zap.Duration("timeout", 
10*time.Second))
Let’s illustrate how to log arbitrary objects, such as structures. In Chapter 2, we defined the 
Metadata structure:
// Metadata defines the movie metadata.
type Metadata struct {
    ID          string `json:"id"`
    Title       string `json:"title"`
    Description string `json:"description"`
    Director    string `json:"director"`
}
Let’s assume that we want to log the entire structure for debugging purposes. One way of doing so 
is to use the zap.Stringer field. This field allows us to log any structure or interface with the 
String() function. We can define a String function for our Metadata structure as follows:
func (m *Metadata) String() string {
    return fmt.Sprintf("Metadata{id=%s, title=%s, 
description=%s, director=%s}", m.ID, m.Title, m.Description, 
m.Director)
}
