## Main Idea

Bu hissədə DB-nin normalizasiyası (1NF, 2NF, 3NF), primary key seçimi və model quruluşu izah edilir. ORM ilə DB modeli və GORM tag-ləri təqdim olunur.

## What I Learned

### Database Normalization

#### 1NF (Birinci Normal Form)
- Hər hüceyrə atomik (scalar) dəyər ehtiva etməlidir
- Məsələn: `Apple → iPhone 14, iPhone 13, iPhone 12` yox, hər satır ayrı olmalı
- Primary key: minimum field-lər, unikal

#### 2NF (İkinci Normal Form)
- 1NF-ə uyğun, hər non-key field primary key-dən asılı olmalı (full functional dependency)
- Məsələn: `Phones-Price` cədvələrində `Скидка` `Firma`-dan asılı, `Price` `Model`-dən → bölünür

#### 3NF (Üçüncü Normal Form)
- 2NF-ə uyğun, non-key field-lər primary key-dən tranzitiv asılı olmamalı
- Məsələn: `Model → Магазин → Телефон` zəncirinin `Model → Телефон` tranzitivi 3NF-ə ziddirdir → `Магазин-Телефон` və `Модель-Магазин` ayrılır

### Repository Model (GORM)
```go
type User struct {
    ID        uint64    `gorm:"column:id"`
    Login     string    `gorm:"column:login"`
    Email     string    `gorm:"column:email"`
    ...
}
func (User) TableName() string { return "users" }
```
- GORM tags ilə DB sətir-sütun xəritələnməsi
- Repository layer-i üçün ayrı model (transport layer modeli ilə fərqlidir)

## What the Author Is Saying

> "ORM позволяет описывать данные в виде структур и манипулировать ими методами"

ORM — struct-based DB işi, SQL yazmadan.

> "в Go редко выбирают что-то одно... смешанный подход: ORM для стандартных, SQL для сложных запросов"

Pragmatic: ORM daynavaət, SQL performance-üçün.

## Important Concepts

- **1NF**: hər cell atomik. `iPhone 14, 13, 12` → ayrı-sayıcı sətirlərə böl.
- **2NF**: non-key field-lər full primary key-dən asılı. Composite key-dən qısmi asılılıq problemi.
- **3NF**: tranzitiv asılılıq yox et. `A→B→C` ilə `A→C`-nin `A→B` və `B→C` ilə böl.
- **GORM tags**: `gorm:"column:email"` — struct field → DB column.
- **Layer isolation**: transport model ≠ domain model ≠ repo model.

## Remember This

> 1NF, 2NF, 3NF — DB normalizasiyası üçün ən vacib 3 addım. Ancaq hər real DB performance üçün denormalizasiya (cache, join table) istifadə edir.

## Terms

- 1NF — Birinci Normal Form: hər hüceyrə atomik dəyər
- 2NF — İkinci Normal Form: full functional dependency
- 3NF — Üçüncü Normal Form: tranzitiv asılılıq yoxu
- Normal Forms (NF) — DB strukturu üçün formal qaydalar
- Primary Key — hər sətrin unikal identifikatoru
- Surrogate Key — UUID/sequential ID ilə primary key
- Composite Key — bir neçə field-dən ibarət primary key
- Denormalization — performans üçün normalizasiyadan "geri getmək"
- GORM tags — struct-ı DB kolonkalarına bağlamaq üçün tag-lər
