## Main Idea

Bu hissədə **layer isolation** prinsibi tam təsvir olunur: transport layer (proto), domain model, repository model — üç ayrı model. Mapper funksiyaları ilə onları bir-birinə bağlayırıq, ardından gRPC server qurulur.

## What I Learned

### Layer Isolation
- **Transport layer**: `.proto`-dan generate olunan `accountpb.User` struct-dır. Network üçün.
- **Domain/Business layer**: `model.User` — business-logika. `.proto`-dan asılı deyil.
- **Repository layer**: `repomodel.User` — DB ilə. GORM tags-lə.
- **Mapper**: `PbToUser`, `UserToPb`, `UserToRepoUser`, `RepoUserToUser` — convert funksiyaları.

### Why 3 models?
> "Если домен знает только о себе и о своей модели, нам понадобится изменить только один слой — адаптер"

- Eyni User strukturu transport (proto) və repo (DB) arasında istifadə etmək — **"binding business code to infrastructure"** anti-pattern.
- Proto modeli: backward compatible olmalı → field silmək olmur, yalnızca `reserved`.
- Domain model: istfərdi, refactoring asanlığı.
- DB model: GORM tags-lə.

### gRPC Server
```go
grpcServer := grpc.NewServer()
healthSrv := health.NewServer()
grpc_health_v1.RegisterHealthServer(grpcServer, healthSrv)
reflection.Register(grpcServer)
grpcServer.Serve(lis)
```
- `net.Listen("tcp", "host:port")` — TCP listener
- `grpc.NewServer()` — gRPC server instance
- `health` + `reflection` — standard gRPC util-ları

### CreateUser vs UpdateUser
- `CreateUser`: password field-ı var (plain).
- `UpdateUser`: email, phone, name-lər. Password yox — on çıxarılmayıb, statusda.
- Domain `model.User` — tam obyekt (ID + CreatedAt). `CreateUser`/`UpdateUser` — partial DTO-lar.

## What the Author Is Saying

> "Если бы весь сервис был построен вокруг proto-генерированного кода, такой подход был бы невозможен без огромного рефакторинга"

Transport layer-ə bağlanmaq — çevikliyin ölümüdür.

> "Изменения локализируются: меняется контракт, обновляется маппер, и этого достаточно"

Mapper istifadə etməkle, hər layer dəyişikliyindən izolasiya olunur.

## Important Concepts

- **Layered Architecture (Clean Architecture)**: transport → domain → repo — hər katmanın öz modeli.
- **DTO (Data Transfer Object)**: transport üçün. `CreateUser`, `UpdateUser`.
- **Mappers**: `XxxToYyy`, `YyyToXxx` funksiyaları. Convertasiya üçün.
- **gRPC Health + Reflection**: production server-ın əlçimanması və introspection üçün.
- **Password hashing**: `CreateUser`-də plain password, amma repo modeli ilə möqayəsəndə hər dərəcə hash olunmalı.

## Remember This

> Transport (proto), domain, və repository model-ləri **üç ayrı struct**. Mapper-lər onları bağlayır. Proto ilə domain modeli bütünleşdirmək — "anti-pattern"-dır.

## Terms

- Layer Isolation — arxivlərin ayrılması (transport/domain/repo)
- Domain Model — business-logika obyektləri
- Transport Layer — network protokolu üçün model
- Repository Layer — DB ilə işlək model
- Mapper — iki model arası dönüştürücü
- DTO — Data Transfer Object
- Anti-pattern — business code-ni infrastructura bağlamaq
- gRPC — Google RPC framework (HTTP/2 + Protobuf)
- Health Check — server-ın canlılığının yoxlanması
- Reflection (gRPC) — server-ın API-nı runtime-da discover etmək
