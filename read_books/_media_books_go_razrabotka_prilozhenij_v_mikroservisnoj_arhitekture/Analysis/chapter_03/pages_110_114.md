## Main Idea

Chapter 3 covers how microservices communicate: synchronous methods (HTTP, gRPC) and asynchronous methods (message brokers — RabbitMQ, Kafka, Redis). It also introduces the API Gateway pattern as a facade service. The chapter includes a deep dive into HTTP protocol structure, the OSI model, and gRPC streaming patterns.

## What I Learned

### Synchronous vs Asynchronous Communication

- **Synchronous**: The client sends a request and waits (is blocked) until the response arrives. Examples: HTTP, gRPC. If an error occurs, the client gets an immediate error.
- **Asynchronous**: The client sends a request and continues without waiting. The response (or result) may come later. Examples: RabbitMQ, Kafka, email notifications.
- Example: Money withdrawal — synchronous returns immediately; a notification about success/failure arrives later asynchronously.

### HTTP Protocol

#### HTTP Request Structure
- **HTTP Method**: GET (read), HEAD (read headers only), POST (create), PUT (replace), PATCH (partial update), DELETE (remove), CONNECT (tunnel), OPTIONS (describe connection), TRACE (debug).
- **Resource path (URL)**: e.g., `/api/v1/user`
- **HTTP protocol version**: e.g., HTTP/1.1, HTTP/2
- **Headers (optional)**: Metadata — authorization tokens, content type, etc.
- **Request body**: For POST and PUT methods.

#### HTTP Response Structure
- **HTTP protocol version**
- **HTTP status code**: 
  - 1xx: Informational
  - 2xx: Successful
  - 3xx: Redirects
  - 4xx: Client errors (e.g., 404 Not Found)
  - 5xx: Server errors
- **Status message**: Brief description, e.g., "OK", "Record not found"
- **Headers**: Similar to request headers
- **Response body**: Optional — response data

### gRPC

- **gRPC** uses HTTP/2 and Protobuf (Protocol Buffers) for efficient service-to-service communication.
- **Protocol Buffers**: Binary serialization format — more compact than XML/JSON. Defined in `.proto` files with `message` and `service` definitions.
- **Communication patterns**:
  - **Unary RPC**: One request → one response (most common)
  - **Server-streaming RPC**: One request → stream of responses
  - **Client-streaming RPC**: Stream of requests → one response
  - **Bidirectional streaming RPC**: Both sides stream messages
- **Testing**: Requires access to proto files or manual construction; tools like BloomRPC or Envoy can be used. gRPC is fast and provides contracts out of the box.

## Important Concepts

- **HTTP methods and semantics**: POST creates records; PUT replaces entirely; PATCH updates partially; DELETE removes.
- **Status code groups**: Client errors (4xx) vs server errors (5xx) help diagnose issues.
- **Protobuf field indexing**: Fields are explicitly numbered (`string login = 2`). Mismatched names with matching indices/types can confuse developers.
- **Shared proto contracts**: Services share a common proto repository to ensure consistent message formats across languages.
- **gRPC streaming types**: Four patterns — unary, server-streaming, client-streaming, bidirectional.
- **HTTP/2**: Used by gRPC — supports multiplexing, header compression, and bidirectional streams.

## Remember This

> Synchronous = blocking (wait for response); Asynchronous = non-blocking (response comes later). Choose based on latency requirements and system resilience.

> gRPC uses HTTP/2 + Protobuf for high-performance, contract-driven microservices communication.

## Terms

- **Synchronous communication**: Caller blocks until response received
- **Asynchronous communication**: Caller doesn't block; response comes later
- **HTTP**: HyperText Transfer Protocol (application layer)
- **HTTP method**: GET, POST, PUT, PATCH, DELETE, etc.
- **HTTP status code**: 1xx-5xx groups
- **gRPC**: Remote Procedure Call framework using HTTP/2 + Protobuf
- **Protocol Buffers (Protobuf)**: Binary serialization format
- **Unary RPC**: One request, one response
- **Server-streaming RPC**: One request, stream of responses
- **Client-streaming RPC**: Stream of requests, one response
- **Bidirectional streaming RPC**: Both sides stream
- **HTTP/2**: Second major version of HTTP (multiplexing, compression)
- **Proto file (.proto)**: ProtoBuf schema definition
- **Repeated**: Array/slice in Protobuf
- **Message**: Structured data type in Protobuf
- **Service**: RPC interface definition in Protobuf
- **Annotations**: `google.api.http` for REST gateway mapping
