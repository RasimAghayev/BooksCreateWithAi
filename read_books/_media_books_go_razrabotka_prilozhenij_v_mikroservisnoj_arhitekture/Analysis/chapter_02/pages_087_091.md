## Main Idea

Chapter 2 introduces the Auth service — a dedicated microservice for authentication and authorization. The chapter begins with a theoretical foundation covering the three fundamental concepts: identification, authentication, and authorization, followed by common attack vectors and security measures.

## What I Learned

### Identification vs Authentication vs Authorization
- **Идентификация** (Identification): The user declares who they claim to be (e.g., entering a login).
- **Аутентификация** (Authentication): The system verifies the claimed identity (e.g., password, token).
- **Авторизация** (Authorization): The system checks what actions the authenticated user is allowed to perform.

### Authentication Methods
1. **Password-based**:
   - HTTP Basic Auth: Base64-encoded `username:password` sent on every request (plain text, insecure).
   - Digest Auth: Challenge-response — server sends a nonce, client hashes password + nonce.
   - NTLM: Microsoft's challenge-response protocol with encrypted channel.
2. **Certificate-based**: X.509 certificates with digital signatures — provides non-repudiation.
3. **OTP (One-Time Password)**:
   - Hardware tokens (plastic cards, key fobs).
   - Software tokens (smartphone apps like Google Authenticator).
   - 2FA: Combines password + OTP for stronger security.
4. **Access keys / API keys**: Static keys for machine-to-machine authentication.
5. **Token-based**:
   - JWT (JSON Web Token): Self-contained, stateless tokens with `header.payload.signature` structure.
   - SAML: XML-based, used for enterprise SSO.
   - OAuth 2.0 + OpenID Connect: Third-party delegation (e.g., "Login with Google").

### Security Threats and Measures
- **Buffer overflow**: When a buffer exceeds its allocated size, potentially allowing arbitrary code execution.
- **Race conditions**: Concurrent requests (e.g., double withdrawal) solved with transaction isolation.
- **Input validation**: Prevents SQL injection and XSS attacks.
- **Client-side attacks**:
  - XSS (Cross-Site Scripting): Injecting scripts to steal cookies/tokens.
  - CSRF (Cross-Site Request Forgery): Forcing authenticated users to execute unwanted actions.
  - Clickjacking: Overlaying invisible elements to trick users into clicking.
- **Password storage**: Passwords must be hashed with bcrypt (salt + slow hashing) — never stored in plain text.

## What the Author Is Saying

> "Идентификация — это информация о том, кем вы являетесь. Аутентификация — это доказательство того, что вы тот, за кого себя выдаёте."

The author emphasizes the distinction between identity claims and identity verification as fundamental to secure auth design.

> "В Go можно реализовать DI вручную, без фреймворков"

Go's philosophy favors manual dependency injection over framework-based approaches.

## Important Concepts

- **JWT Structure**: `header.payload.signature` — each part is Base64Url encoded. Header contains algorithm; payload contains claims (user ID, expiry); signature is HMAC/RSASSA signed.
- **2FA**: Combines password + time-based OTP — essential for enhanced security.
- **CSRF Protection**: SameSite cookies + CSRF tokens prevent cross-site request forgery.
- **bcrypt**: Hashing algorithm with built-in salt and configurable cost (DefaultCost = 10) — makes brute-force attacks computationally expensive.
- **Non-repudiation**: Certificate-based auth provides proof of origin that cannot be denied.

## Remember This

> Identification ≠ Authentication ≠ Authorization — these are three distinct stages. Each must be handled appropriately in microservice architecture.

> Passwords must always be hashed with bcrypt before storage — a database leak should never expose user passwords.

## Terms

- **Identification (идентификация)**: Declaring who you are
- **Authentication (аутентификация)**: Verifying claimed identity
- **Authorization (авторизация)**: Checking permitted actions
- **Basic Auth**: HTTP Basic Authentication (Base64-encoded credentials)
- **Digest Auth**: Challenge-response authentication
- **NTLM**: Microsoft challenge-response protocol
- **Certificate (сертификат)**: X.509 digital certificate
- **OTP**: One-Time Password
- **2FA**: Two-Factor Authentication
- **JWT**: JSON Web Token
- **SAML**: Security Assertion Markup Language
- **OAuth 2.0**: Third-party authorization delegation
- **OpenID Connect**: Identity layer on top of OAuth 2.0
- **Buffer Overflow**: Buffer exceeding its bounds
- **Race Condition**: Concurrent access conflicts
- **XSS**: Cross-Site Scripting attack
- **CSRF**: Cross-Site Request Forgery attack
- **Clickjacking**: UI redressing attack
- **bcrypt**: Password hashing algorithm with salt and work factor
