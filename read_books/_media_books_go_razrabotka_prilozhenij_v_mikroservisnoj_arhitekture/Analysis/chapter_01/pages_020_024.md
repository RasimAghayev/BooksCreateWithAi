## Main Idea

Chapter 1-in bu hissəsində Git versiya nəzarəti, kodun üslubu (gofmt) və Docker containerizasiyasını öyrənir. Git Flow modelinin ətraflı strukturu, branch-lər, merge, conflict resolution və .gitignore konsepsiyası izah edilir. Sonra Docker və Docker-Compose ilə PostgreSQL-in necə işə salınacağı göstərilir.

## What I Learned

- **Git Flow** modeli:
  - `Master` — production-de ready kod
  - `Develop` — yeni feature-lar üçün əsas branch
  - `Feature` — yeni funksiyalar, Develop-dən ayrılır, Develop-ə geri birləşir
  - `Release` — release-hazırlığı üçün, bugsız burada fix edilir
  - `Hotfix` — production-dan bug tapıldıqda, Master-dən yaradılır
  - `Test`, `Preprod` — əlavə stendlər

- **Git file types**:
  - Tracked ( izlənilən) — index edilmiş və ya commit edilmiş
  - Untracked ( izlənilməyən) — index edilmemiş yeni fayl
  - Ignored ( nizarsı) — `.gitignore`-a daxil edilmiş fayllar

- **gofmt** — Go-nun standard formatter-ı. "стиль написания кода достаточно специфичный и строгий" — bu Go-nun culture-nin bir hissəsidir.

- **Docker**: Containerizasiya aləti. Containerlar hər hansı bir OS-də eyni şəkildə işləyir.
- **Docker-Compose**: Birdən çox containerı idarə etmək üçün. `docker-compose up` ilə bir başa mövcudluq.

## What the Author Is Saying

Müəllif deyir ki, Go dilində kod stilləri çox fərqlidir — digər dillərdə kod formatı komandanıq qərarıdır, lakin Go-da `gofmt` standarddır və "код не должен различаться в зависимости от предпочтений его автора" (kod müəllifin istərindən asılı olmamalıdır).

> "Docker решает эту проблему через контейнеризацию." — Docker-in ən əsas faydası, ehtiyat tətbiqlərinin müxtəlif versiyaları arasında conflictlərin qarşısını almasıdır.

## Important Concepts

- **Conflict Resolution (konflikt həlli)**: Merge zamanı eyni faylda iki branch-də dəyişiklik olarsa, "ручную" həll etmək lazımdır. Modern kod editorları konflikt zamanlarını göstərir.
- **CI/CD**: Docker, Kubernetes ilə bütövlük tədbərqablaşdırmalı deploy workflow-ı.

## Remember This

> `.gitignore`-da "специальной команды для этого в Git нет" — faylları əlavə etmək üçün manual olaraq `.gitignore`-a yazılmalıdır.

> Docker-Compose `docker-compose up` ilə "всю необходимую инфраструктуру одной командой" işə salır.

## Terms

- Git Flow (Git axın) — branch idarəetmə modeli
- Tracked Files (izlənilən fayllar) — Git tərəfindən izlənən
- Untracked Files (izlənilməyən fayllar) — yeni fayllar
- Ignored Files (nizarsı fayllar) — `.gitignore`-a daxil olmuş fayllar
- Container (konteiner) —izolyasıya olunmuş tətbiq mühit
- Docker Compose (Docker-komposiz) — birdən çox konteineri idarə etmək

## Code

### 1. Git Flow Branch Structure
```
Master (main)  — production-ready code
    ↑
    | (merge)
    ↓
Develop         — main development branch
    ↑
    | (feature branches)
Feature         — new features (created from Develop, merged back)
    ↑
    | 
Release         — release preparation (from Develop, merge to Master+Develop)
    ↑
    | 
Hotfix          — critical bug fixes (from Master, merge to Master+Develop)
```

### 2. docker-compose.yaml (PostgreSQL for User service)
```yaml
services:
  postgres:
    image: postgres:latest
    environment:
    POSTGRES_USER: postgres
    POSTGRES_PASSWORD: postgres
    POSTGRES DB: account
    ports:
    - "5432:5432"
    volumes:
    - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      timeout: 5s
      retries: 5
    networks:
    - app-network

volumes:
  postgres_data:
networks:
  app-network:
    driver: bridge
```

### 3. Git commands reference
```bash
git init                    # Initialize repository
git add .                   # Stage all changes
git commit -m "message"     # Create commit
git branch feature-name     # Create branch
git checkout branch-name    # Switch branch
git merge branch-name       # Merge branches
```
