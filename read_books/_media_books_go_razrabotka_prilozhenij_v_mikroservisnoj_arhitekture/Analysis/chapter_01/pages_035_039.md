## Main Idea

Bu hissədə `make run` ilə servisin işə salınması nəticəsində əldə edilən log output-ı tədqiq edilir, ardından ORM (GORM) və repository pattern təsiri təqdim edilir.

## What I Learned

### Logger Demo Output
Servisin startup zamanı log çıxışı:
1. `Loaded configuration: source=account` ilə konfiqurasiya yükləndiyi xabarı
2. Spew ilə dumper edilmiş konfiqurasiya detalları (ServiceName, AppEnv, Host, Port, LogLevel)
3. `service starting up` mesajı

### ORM (Object-Relational Mapping)
- **Object (O)** — predmet növü (User, Order)
- **Relational (R)** — cədvəllər arası arqalar (joins)
- **Mapping (M)** — cədvəlləri modellərə çevirmə
- ORM, obyekt-sənədə çevrilmənin avtomatlaşdırılması — eyni DB əmri üçün eyni kodu təkrarlamağı arındırır
- **GORM** — Go-da ən ümumiyyetləşdirilmiş ORM, ehtiva: avtomatik migration, relations (one-to-one, one-to-many, many-to-many), soft deletes

### Repository Pattern
- Business-logikadan DB detalıları ayrılır (`internal/repository` directory)
- Repository `repository.go` — entry point; `NewRepository(*gorm.DB, *zerolog.Logger)` ilə init edilir
- main.go-da DB connection qurulur, repository-ə ötürülür

## What the Author Is Saying

> "ORM — это инструмент для сопоставления сущностей в приложении с таблицами базы данных"

Müəllif, ORM-in "ORM = Object + Relational + Mapping" olduğunu izah edərək, onun obyektləri DB ilə necə bağlayıb bağlamadığını izah edir.

> "В Go редко выбирают что-то одно... Чаще всего практикуется смешанный подход: ORM для стандартных, SQL для сложных запросов"

Bu, Go-da pragmatik yanaşmanın nümunəsidir.

## Important Concepts

- **ORM vs Raw SQL**: ORM-un sürət itirilməsi riski var, xüsusilə yüksək yüklənmiş servislərdə.
- **Repository Pattern**: Business-logikanı DB ilə ayırır — DB layeri dəyişdiriləndə business kod dəyişmir.
- **GORM**: `go get gorm.io/gorm gorm.io/driver/postgres` — PostgreSQL üçün.
- **DB Connection**: main.go-da `gorm.Open(postgres.Open(cfg.DbDsn), &gorm.Config{})`

## Remember This

> ORM və raw SQL-i birləşdirmək — Go-da ən yaxşı təcrübədir. "Object Relational Mapping" ehtiyatlaşdırılmalı, ancaq sürət tələbtə olan yerdə SQL-i seçsək də.

## Terms

- ORM — Object Relational Mapping (объектно-реляционное отображение)
- Repository Pattern (паттерн "репозиторий") — business-logikanı DB-lə ayırmaq
- GORM — Go üçün ORM kitabıxanası
- DSN — Data Source Name (verilənlər bazası bağlantı sətri)
- PostgreSQL — açıq mənbəli relational DB
- Business Logic — biznes qanunları (obyekt modeli, validasiya)
- Data Access Layer — verilənlər bazası ilə işlək kod
