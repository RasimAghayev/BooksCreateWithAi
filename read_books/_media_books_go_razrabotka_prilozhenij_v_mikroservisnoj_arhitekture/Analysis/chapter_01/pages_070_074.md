### Transport Layer (listing 1.26)
```go
type Server struct {
    accountpb.UnimplementedAccountServer  // gRPC generated
    accountService AccountService         // service interface

```
- `accountpb.CreateUserRequest` → `mapper.PbToUserCreate(req.GetUser())` → domain model
- `mapper.UserToPb(res)` — domain → proto
- **Server heç bir business-logikaya malik deyil** — yalnızca request parsing + response formatting.

## What the Author Is Saying

> "Серверный слой не содержит бизнес-правил... Это остается задачей сервисного слоя"

Transport layer yalnızca proto→domain mapping; heç bir business-logika.

> "Мы описываем в интерфейсе методы, которые должны быть реализованы" 

Repository interface-i — contract. Test üçün mock-lə əvəz edilə bilər.

## Important Concepts

- **4 layer** (Clean Architecture): Transport → Service → Repository → DB
- **Transport Layer**: Proto request → mapper → domain model → service. Response: domain → mapper → proto.
- **Service**: Business logic (model.CreateUser → model.User conversion, bcrypt, repo call).
- **Repository Interface**: Service-ın repo interface-i; concrete impl runtime-da inject olunur.
- **gRPC Server Registration**: `accountpb.RegisterAccountServer(s, server)` — proto generates register funksiyası.

## Remember This

> Transport layer heç bir business logic-ə sahə dəyişikliyə baxmayaraq, yalnızca request/response mapping.

## Terms

- Transport Layer — network protokolu üçün server kodu
- gRPC Server — Go gRPC server (`grpc.NewServer()`)
- RegisterAccountServer — proto generate edilmiş register funksiyası
- AccountService — business-logika servisi
- Repository Interface — repository-nin kontratı (test üçün mock-lanabilir)
- Server struct — gRPC server handler
- Clean Architecture — 4 layer-li izolyasiya (Transport > Service > Repo > DB)
- DI (Dependency Injection) — asılılığın dışarıdan inject edilməsi
