## Main Idea

Bu hissədə loggerın konfiqurasiya dump-nın spew+zerolog ilə necə etməyini görürük, make run nəticəsində console output-u analiz edirik, ardından GORM ilə DB connection və repository pattern tam kodla təqdim olunur.

## What I Learned

### Logger — Config Dumping
- `spew.Dump(cfg)` — config-ın tam struct-nu string-ə başıyor
- `color.New(color.FgCyan).SprintFunc()` — field name-ləri maviyə boyayır
- `regexp.MustCompile(...)` ilə `FieldName:` pattern-ni tapıb rəngləndirir
- Nəticədə console-da rəngli, formatlaşmış config çıxır

### GORM + Repository
- `gorm.io/gorm` + `gorm.io/driver/postgres` — quraşdırmaq üçün `go get`
- `cfg.DbDsn := postgres://postgres:postgres@localhost:5432/account?sslmode=disable`
- `repository.NewRepository(db, &logger)` — gorm.DB və logger-ı inject edir

## What the Author Is Saying

> "Этот подход позволяет централизовать настройку логирования и избавляет от необходимости думать о форматировании в каждом отдельном модуле"

Logger centralizasiyası — modullar arası log formatının universallaşdırılması.

> "передача логера в качестве зависимости мы избегаем глобальных переменных и сохраняем модульность кода"

Dependency injection — global state-i arındırmaq üçün ən yaxşı üsul.

## Important Concepts

- **Dependency Injection**: Logger, repository, config — hepsi inject olunur, global yox.
- **ConsoleWriter (zerolog)**: JSON formatından fərqlənərək human-readable output.
- **spew.Dump**: Struct-ı readable formatda çıxarır, debug üçün ideal.
- **LD_FLAGS**: `-X main.Version=dev -X main.BuildTime=...` — build zamanı versiya metadata.

## Remember This

> `make run` output-unu oxumaq — ilk servis deploy-a baxmaq qədər əlçatan yolla "proof of life"-dır.

## Terms

- zerolog — sürətli Go log kitabıxanası (JSON output)
- ConsoleWriter — zerolog-da human-readable output üçün writer
- spew — Go strukturlarını dumper etmək üçün kitabıxana
- LD_FLAGS — Go linker flags
- Dependency Injection (DI) — asılılığın inject edilməsi
- GORM — Go ORM
- PostgreSQL — relational DB
