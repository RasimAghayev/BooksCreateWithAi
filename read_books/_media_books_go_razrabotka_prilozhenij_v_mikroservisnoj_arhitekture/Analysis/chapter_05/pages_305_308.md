## What I Learned

### Kubernetes Overview

> "Kubernetes - это мощный инструмент для оркестровки контейнеризированных приложений с открытым исходным кодом, позволяющий автоматизировать процесс развертывания, масштабирования и координации сервисов в условиях кластера"

Kubernetes automates:
- Deployment of containerized applications
- Scaling
- Coordination of services in a cluster environment

### Kubernetes Capabilities

1. **Workload distribution** across multiple hosts
2. **Declarative API** for system interaction
3. **kubectl** — CLI utility for manual API server interaction
4. **Self-healing**: brings objects from current state to desired state
5. **Service layer** for routing requests to applications
6. **Pluggable interfaces** for network, storage, and other modules

### Core Concepts

#### 1. Node (Узел)
> "Отдельная физическая или виртуальная машина, на которой развернуты и выполняются контейнеры приложений"

- Each node contains services for running containers and centralized management components
- Can be physical or virtual machines

#### 2. Pod (Под)
> "Базовая единица для запуска и управления приложениями"

- Contains one or more containers guaranteed to run on the same node
- Provides resource sharing and inter-process communication within the pod
- Has a unique IP address within the cluster (avoids port conflicts)
- Can be managed via Kubernetes API or controllers

#### 3. Volume (Том)
> "Общий ресурс храниения для совместного использования контейнерами в пределах одного пода"

- Shared storage accessible by all containers in a pod
- Persists across container restarts within the same pod

#### 4. Replication Controller (Контроллер реплик)
> "Обеспечивает масштабирование, запуская необходимое количество копий пода в кластере"

- Launches new pod instances if any fail
- Scales application by running multiple pod replicas

#### 5. Service (Сервис)
> "Абстракция, которая определяет логически объединенную в группу подов и политику доступа к ней"

- Groups pods together logically
- Defines access policies for the group

### Quick Demo

```bash
# Install kubectl
# (see https://kubernetes.io/docs/tasks/tools/install-kubectl-linux/)

# Create a pod running nginx
kubectl run nginx --image=nginx:latest --port=80

# Inspect the pod
kubectl describe pods nginx
```

The output of `kubectl describe pods nginx` shows:
- Name, Namespace, Priority, Service Account
- Node assignment
- Start Time and Labels
- Status: Pending → ContainerCreating → Running
- Container details: Image, Ports, State, Restart Count
- Conditions: PodReadyToStartContainers, Initialized, Ready

## Important Concepts

- Kubernetes is the industry standard for container orchestration
- Pod is the smallest deployable unit (not the container itself)
- Pods share the same IP and can communicate via localhost
- Volumes provide persistent shared storage within a pod
- Replication controllers ensure desired number of pod replicas
- Services provide stable networking for pods

## Remember This

> Kubernetes: Pod = deployment unit with shared IP; Node = host VM; Volume = shared storage; Replication Controller = auto-scales pods; Service = groups pods + access policy. Installation: follow kubernetes.io docs, then `kubectl run nginx --image=nginx:latest --port=80`.

## Terms

- **Kubernetes (k8s)**: Container orchestration platform
- **kubectl**: CLI for Kubernetes API server
- **Node**: Physical/virtual machine in the cluster
- **Pod**: Smallest deployable unit, may contain multiple containers
- **Volume**: Shared storage for containers in a pod
- **Replication Controller**: Ensures desired number of pod replicas
- **Service**: Logical grouping of pods with access policy
- **ContainerCreating**: Pod state during image pull/prep
- **Pending**: Pod state awaiting scheduling
