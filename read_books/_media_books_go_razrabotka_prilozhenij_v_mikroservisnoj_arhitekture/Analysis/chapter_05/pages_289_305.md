## Main Idea

This section covers **Docker containerization** of the microservices — creating Dockerfiles, docker-compose.yaml configuration, publishing images to Docker Hub, and preparing for deployment to a remote server.

## What I Learned

### Dockerfile Structure (listing 5.6)

The book uses a **multi-stage build** pattern:

```dockerfile
FROM golang:1.24.5-alpine AS build
WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download
COPY .
# если main.go в корне проекта
RUN go build -o app ./cmd
# ---
# финальный образ
FROM alpine:3.18
WORKDIR /app
COPY --from=build /app/app
COPY --from=build /app/internal/migrations ./internal/migrations
CMD ["./app"]
```

**Key points:**
- Multi-stage build: first stage compiles Go app, second stage creates minimal runtime image
- Uses `golang:1.24.5-alpine` for build (includes compiler) and `alpine:3.18` for final runtime (~5MB)
- Pinning specific versions (not `:latest`) avoids unexpected compatibility issues
- `COPY go.mod go.sum ./` before `COPY .` enables Docker layer caching — dependencies cached even when code changes
- `RUN go mod download` downloads dependencies as a separate cached layer

### .dockerignore (listing 5.7)

```
.idea
vendor
```

- `.dockerignore` works like `.gitignore` — excludes files/directories from being copied into the image
- Reduces image size by preventing unnecessary files (IDE configs, vendored deps) from being included

### docker-compose.yaml (listing 5.8)

The docker-compose file orchestrates all services:

**Database services:** PostgreSQL for each microservice (account_db, auth_db, transaction_db) with:
- Health checks using `pg_isready`
- Persistent volumes
- Port mappings: 5432, 5433, 5434

**Kafka:** `confluentinc/cp-kafka:7.5.0` with KRaft mode (no ZooKeeper), exposing ports 9092 (internal) and 29092 (external)

**Kafka UI:** `provectuslabs/kafka-ui:latest` on port 29093 for cluster monitoring

**Application services:** transaction, account, auth, gateway — each built from their respective Dockerfiles

### Publishing to Docker Hub (pages 300-304)

1. **Login:** `docker login` → "Login Succeeded"
2. **List images:** `docker image ls` → shows all 4 service images (transaction, account, auth, gateway)
3. **Tag images:** `docker tag book_all-auth yuliapopova/book_all-auth:latest`
   - Format: `docker tag <local-image> <docker-username>/<remote-image>:<tag>`
4. **Push:** `docker push yuliapopova/book_all-auth:latest`
5. **Update docker-compose:** Change `build: ./transaction` to `image: yuliapopova/transaction:latest` for all services
6. **Deploy:** Copy docker-compose + env files to remote VM, run `docker-compose up`

## Important Concepts

### Multi-stage Build
- First stage: build image with compiler tools
- Second stage: minimal runtime image with only the binary + necessary files
- Reduces final image size significantly

### Docker Layer Caching
- Layers are cached and reused when unchanged
- `COPY go.mod go.sum ./` + `RUN go mod download` before `COPY .` ensures dependencies are cached separately from source code
- Source code changes don't trigger re-download of dependencies

### Service Communication in Docker
- Inside containers, services connect to each other by **service name** (not localhost)
- `docker-compose` provides automatic DNS resolution for service names
- External port mappings for host access, internal network for inter-service communication

### Docker Hub Best Practices
- Tag images with descriptive names: `<username>/<project>-<service>:latest`
- Use specific version tags in production (avoid `latest` for critical deployments)
- Consider using personal access tokens instead of password for better security

## Remember This

> Multi-stage Dockerfile: build stage (golang:alpine) → runtime stage (alpine). Separate `COPY go.mod` + `RUN go mod download` for layer caching. Docker Hub: tag → push → update docker-compose with `image:` instead of `build:`.

## Terms

- **Dockerfile**: Declarative script for building Docker images
- **Multi-stage build**: Using multiple `FROM` statements to reduce final image size
- **.dockerignore**: Excludes files from Docker build context
- **Docker layer cache**: Reuses unchanged build layers for faster builds
- **docker-compose**: Tool for defining and running multi-container Docker apps
- **docker tag**: Assigns a new tag to an image (for registry push)
- **docker push**: Uploads an image to a container registry (Docker Hub)
- **Service name**: Internal DNS name used for inter-container communication in Docker Compose
