## Main Idea

This section covers the **Transaction Repository** implementation — the GORM-based data access layer that handles transaction creation, filtering, retrieval with entries, and the Deposit/Withdraw/Transfer operations wrapped in database transactions for atomicity. Each operation follows a "create pending transaction → add entries → mark completed" pattern.

### Transaction Repository (listing 4.8)

#### GetTransactions (filtered, paginated)
```go
func (r *Repository) GetTransactions(ctx context.Context, params model.GetTransactionsParams) ([]model.Transaction, error) {
    var transactions []repomodel.Transaction
    query := r.db.WithContext(ctx).Model(&repomodel.Transaction{})
    if params.UserID != nil {
        query = query.Where("user_id = ?", *params.UserID)
    }
    if params.Type != nil {
        query = query.Where("type = ?", *params.Type)
    }
    if params.Status != nil {
        query = query.Where("status = ?", *params.Status)
    }
    if params.DateFrom != nil {
        query = query.Where("created_at >= ?", *params.DateFrom)
    }
    if params.DateTo != nil {
        query = query.Where("created_at <= ?", *params.DateTo)
    }
    res := query.Offset(params.Offset).Limit(params.Limit).Order("created_at DESC").Find(&transactions)
    if res.Error != nil {
        r.logger.Err(res.Error).Msg("failed to get transactions")
        return nil, fmt.Errorf("failed to get transactions: %w", res.Error)
    }
    return mapper.RepoTransactionsToTransactions(transactions), nil
}
```

#### GetTransactionDetails (transaction + entries)
```go
func (r *Repository) GetTransactionDetails(ctx context.Context, transactionID uint64) (model.TransactionDetails, error) {
    var transaction repomodel.Transaction
    res := r.db.WithContext(ctx).Model(&repomodel.Transaction{}).
        Where("id = ?", transactionID).First(&transaction)
    if errors.Is(res.Error, gorm.ErrRecordNotFound) {
        return model.TransactionDetails{}, fmt.Errorf("transaction not found")
    }
    var entries []repomodel.TransactionEntry
    res = r.db.WithContext(ctx).Model(&repomodel.TransactionEntry{}).
        Where("transaction_id = ?", transactionID).Order("created_at ASC").Find(&entries)
    return model.TransactionDetails{
        Transaction: mapper.RepoTransactionToTransaction(transaction),
        Entries: mapper.RepoTransactionEntriesToTransactionEntries(entries),
    }, nil
}
```

#### Deposit (within DB transaction)
```go
func (r *Repository) Deposit(ctx context.Context, params model.DepositParams) (model.TransactionDetails, error) {
    var result model.TransactionDetails
    err := r.db.WithContext(ctx).Transaction(func(tx *gorm.DB) error {
        // 1. Create transaction record (status = pending)
        transaction := model.Transaction{
            UserID: params.UserID,
            Amount: int64(params.Amount * 100),  // convert to kopeyki
            Status: model.TransactionStatusPending,
            Type: model.TransactionTypeDeposit,
        }
        transactionRepo := mapper.TransactionToRepoTransaction(transaction)
        res := tx.Clauses(clause.OnConflict{UpdateAll: true}).Create(&transactionRepo)
        // 2. Create DEBIT entry (balance increases)
        entry := model.TransactionEntry{
            TransactionID: transactionRepo.ID,
            AccountID: params.UserID,
            Direction: model.TransactionEntryDirectionDebit,
            Amount: params.Amount,
        }
        entryRepo := mapper.TransactionEntryToRepoTransactionEntry(entry)
        res = tx.Clauses(clause.OnConflict{UpdateAll: true}).Create(&entryRepo)
        // 3. Update transaction status to completed
        updateData := mapper.UpdateTransactionToRepoTransaction(model.UpdateTransaction{
            Status: model.TransactionStatusCompleted,
        })
        res = tx.Where("id = ?", transactionRepo.ID).Updates(&updateData)
        // 4. Return details
        result = model.TransactionDetails{...}
        return nil
    })
    if err != nil {
        return model.TransactionDetails{}, err
    }
    return result, nil
}
```

#### Withdraw (within DB transaction)
Similar to Deposit, but creates a **CREDIT** entry (balance decreases):
```go
entry := model.TransactionEntry{
    TransactionID: transactionRepo.ID,
    AccountID: params.AccountID,
    Direction: model.TransactionEntryDirectionCredit,  // DEBIT decreases, CREDIT increases
    Amount: params.Amount,
}
```

#### Transfer (within DB transaction)
Creates a single Transaction with **two entries** — credit for sender, debit for recipient:
```go
// 1. Create pending transfer transaction
// 2. Create credit entry (sender loses funds)
creditEntry := model.TransactionEntry{
    TransactionID: transactionRepo.ID,
    AccountID: params.UserID,         // sender
    Direction: model.TransactionEntryDirectionCredit,
    Amount: params.Amount,
}
// 3. Create debit entry (recipient gains funds)
debitEntry := model.TransactionEntry{
    TransactionID: transactionRepo.ID,
    AccountID: params.Recipient,      // recipient
    Direction: model.TransactionEntryDirectionDebit,
    Amount: params.Amount,
}
// 4. Mark transaction as completed
```

## What the Author Is Saying

> "Во всех операциях связанных с добавлением/изменением данных, логика построена по одному принципу: сначала создается запись о самой транзакции в статусе pending, затем добавляются связанные движения по счетам (дебит или кредит — в зависимости от операции). После успешного выполнения всех действий статус обновляется на completed."

The transaction lifecycle ensures data consistency — never commit partial operations.

> "Эти методы делают работу с балансом надежной из-за таких проверок и использования транзакций."

Database transactions (ACID) are the safety net for financial operations.

## Important Concepts

- **GORM Transaction()**: `db.Transaction(func(tx *gorm.DB) error {...})` — wraps operations in a DB transaction. If the callback returns an error, the transaction rolls back automatically.
- **Pending → Completed pattern**: Always insert transaction record first (status=pending), then entries, then update status=completed. This provides an audit trail.
- **Kopeyki (cents)**: Amount stored as `int64(params.Amount * 100)` — converts float dollars to integer cents to avoid floating-point precision errors.
- **Double-entry**: Credit (decrease) + Debit (increase) ensure the books always balance.
- **Idempotency via OnConflict**: `clause.OnConflict{UpdateAll: true}` prevents duplicate key errors on retry.
- **No deletion**: Transactions are immutable — no delete methods in Repository (financial audit requirement).
- **Error propagation**: If any step fails inside `Transaction()`, the entire operation rolls back.

## Remember This

> Transaction lifecycle: CREATE transaction (pending) → CREATE entries (debit/credit) → UPDATE status (completed). If anything fails, the entire transaction rolls back.

> Financial amounts stored as int64 (kopeyki/cents) — `int64(params.Amount * 100)` to avoid floating-point precision issues.

## Terms

- **GORM Transaction()**: Wraps callback in a DB transaction for atomicity
- **Pending status**: Initial state — transaction is being processed
- **Completed status**: Transaction succeeded and is finalized
- **Debit (дебет)**: Entry type that increases account balance
- **Credit (кредит)**: Entry type that decreases account balance
- **Kopeyki**: Minor currency unit (cents); stored as int64 to avoid float errors
- **Double-entry bookkeeping**: Every debit has a matching credit
- **OnConflict**: GORM clause for upsert behavior
- **Audit trail**: Immutable transaction history for compliance
- **Atomicity in DB**: All-or-nothing transaction execution
- **Status lifecycle**: pending → completed/failed/cancelled
