#58: Not understanding race problems
Previous write at 0x00c00008e000 by goroutine 6:
main.main.func1()
==================
The final value of i is also unpredictable. Sometimes it can be 1, and sometimes 2.
 What’s the issue with this code? The i++ statement can be decomposed into three
operations:
1
Read i.
2
Increment the value.
3
Write back to i.
If the first goroutine executes and completes before the second one, here’s what
happens.
The first goroutine reads, increments, and writes the value 1 back to i. Then the sec-
ond goroutine performs the same set of actions but starts from 1. Hence, the final
result written to i is 2.
 However, there’s no guarantee that the first goroutine will either start or complete
before the second one in the previous example. We can also face the case of an inter-
leaved execution where both goroutines run concurrently and compete to access i.
