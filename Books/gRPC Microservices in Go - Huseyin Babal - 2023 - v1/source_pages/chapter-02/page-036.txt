2.3.3
Choreography-based saga 
A choreography-based saga is a pattern in which each service executes its local transaction
and publishes an event to trigger the next service to execute its local transaction.
Whenever a saga is created, it can be completed in the following patterns:
Service returns the result to the client once the saga is completed. It receives an
event to update its domain object’s status as succeeded or failed.
A saga is created, and the client starts to poll the next service to get either a suc-
ceeded or failed response. The unique identifier to start polling should be
directly returned when the saga is created.
A saga is created, and the client uses a WebSocket connection in which the ser-
vice sends the result back using WebSocket protocol. A saga will be completed
once the succeeded or failed result is returned.
