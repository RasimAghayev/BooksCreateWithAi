If we fall into the case where we have multiple producer goroutines, it may be impossi-
ble to guarantee which one writes first. Hence, whether we have an unbuffered
messageCh channel or a single channel, it will lead to a race condition among the pro-
ducer goroutines. In that case, we can implement the following solution:
1
Receive from either messageCh or disconnectCh.
2
If a disconnection is received
– Read all the existing messages in messageCh, if any.
– Then return.
Here is the solution:
for {
select {
case v := <-messageCh:
fmt.Println(v)
case <-disconnectCh:
for {
select {
case v := <-messageCh:
fmt.Println(v)
default:
fmt.Println("disconnection, return")
return
}
}
}
}
This solution uses an inner for/select with two cases: one on messageCh and a
default case. Using default in a select statement is chosen only if none of the other
cases match. In this case, it means we will return only after we have received all the
remaining messages in messageCh.
